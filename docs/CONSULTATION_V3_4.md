# v3.4 정보수집·의사소통 후보

v3.3 커밋 `8f191c664ed44e29d312902b6f86f59bc743db35`에서 분기한 후보다. 검색 자료·인덱스를 추가하지 않았다. 이번 범위는 기존 로그 분석, 코드 수정, 네트워크를 차단한 오프라인 검증이다. **v3.4 실제 모델 실행·샘플 채점·Linux 컨테이너 재검증은 미실행**이다.

## 실행 환경

Python 3.12와 기존 v3.3의 파일·검색 설정을 그대로 사용한다. 제출 진입점은 `app/run.py`, 공식 `prepare()`/`consult()` 순서와 `openai/gpt-6-luna` 모델도 유지한다. 원문 위치와 `NOVA_RAG_SOURCES`의 `auto`, `legacy`, `guidelines`, `legacy,guidelines`, `none` 사용법은 [v3.3 문서](EXTENSION_V3_3.md)에 있다. 지침 원문·샘플 대본·정답·키·실제 세션 로그는 후보에 넣지 않는다. 자료별 이용 조건 미확정 사항도 유지된다.

실제 진료 실행에는 기존 `NOVA_API_BASE`, `NOVA_RUN_TOKEN`, 선택 `NOVA_SESSION_ID`가 필요하며 실제 통신을 발생시킨다. **이번 작업에서는 이 실행을 하지 않았다.** 개발 키 입력이나 추가 평가도 필요하지 않았다.

## 변경한 판단·행동 흐름

`nova_agent/consultation.py`의 `DialogueState`는 세션 안에서만 존재한다. 임상 지식이나 공개 사례 정답을 담지 않는다.

- 매 Doctor 행동 응답의 `review`에는 최근 실제 답변의 짧은 원문 인용과 환자별 정보 공백을 넣는다. 인용은 해당 관찰 ID의 답변에 실제 존재해야 한다. 질문·RAG ID를 관찰 인용으로 인정하지 않는다.
- 공백은 최대 6개의 `unknown`/`ambiguous` 항목, 중요도, 관찰 ID, 필요 이유로 관리한다. 이는 **모델의 계획**이며 확인된 환자 소견이 아니다. 모름·부분 답변 가능성은 별도로 표시하고 전체 질문의 정상/음성으로 바꾸지 않는다.
- 행동마다 대상 하나와 필요 이유를 명시한다. 질문/진찰의 명백한 복합 표현은 복구 대상으로 돌린다. 이 검사는 언어학적·임상적 완전 판정기가 아니며 일부 정상 표현도 거절하거나 다른 복합 표현을 놓칠 수 있다.
- 환자의 걱정·요청, 공감, 질문 이유를 검토하도록 지시한다. 진단 불확실성·다음 계획·주의사항은 실제 짧은 SAY로 전달한다. 긴 설명은 모델이 독립된 짧은 발화로 구성해 턴별로 선택한다. 코드는 문자열을 잘라 보내거나 미리 만든 발화를 자동 실행하지 않는다.
- `communication` 태그는 계획 단계에서 설명 완료가 되지 않는다. SDK 성공 응답의 형식·거절 여부를 확인한 뒤 `acknowledged_explanations`에 넣는다. 환자 이해·실제 이행 완료까지 증명하는 태그는 아니다.
- DONE에는 준비 여부·종료 이유와 남은 공백을 미루는 이유를 요구한다. 아직 전달하지 않은 핵심 설명은 실제 SAY로 수행하거나 환자별 불필요 사유를 명시해야 한다. 예외 사유를 실제 설명으로 세지 않는다. 이 사유의 임상적 타당성은 모델 판단에 의존한다.

남은 턴·시간·입력/출력/호출 예산이 줄면 `CLOSE` 상태로 전환해 미전달 설명을 우선한다. 새로 나타난 고위험 정보 공백은 먼저 확인할 수 있다. COLLECT 단계에서는 기록 재시도 예약에 더해 설명 선택 1회의 입력 추정치(+4,096 여유 바이트)·출력 2,048·호출 1회를 조건부로 남긴다. CLOSE에서 그 여유를 사용한다. 이는 고정 설명 횟수나 모든 미래 응답 길이의 보장이 아니다. 실제 요청마다 기존 예산 검사를 다시 적용한다.

`prepare()`의 모든 검색 모드가 v3.4 제어를 켠다. 하위 `Config(consultation_review=False)` 기본값은 기존 저수준 합성 fixture 호환을 위해 남겼으며 운영 진입점에는 환경변수로 끄는 경로가 없다. 직접 `State`를 만드는 개발·테스트 코드는 새 제어를 검증하려면 `Config(consultation_review=True)`를 명시한다. 기존 145개 회귀의 공통 실행·예산 검증과 새 프로토콜 검증 범위를 구분한다.

## 형식 복구와 기록

`action_repair.py`는 30자 초과가 반복되면 다음 생성 목표를 12~18자로 좁힌다. 이전 후보와 실제 길이를 전달하되 새 응답을 다시 검증한다. 3회 한도, 예산 정산, 동일 요청의 request_id 재사용, TEST 금지, 최종 기록 예약은 유지한다. 복구 불능이면 오류를 숨기지 않고 확보한 정보로 기록을 시도한다. 실제 모델에서 길이 오류가 줄었는지는 아직 확인하지 않았다.

`record.py`는 S/O에 모델이 선택하지 않은 확보 답변·시행 진찰도 원문으로 보존한다. 설명에 대한 환자의 새 정보도 빠뜨리지 않으며 질문/설명과 환자 답변을 구분해 붙인다. 활력징후는 관찰 ID 기준으로 중복을 제거한다. 긴 세션에서 `visible_facts` 한도로 이미 생략된 관찰까지 복구하는 기능은 아니다.

A의 자유 서술에는 새로 만든 정상·음성 표현을 허용하지 않고, 확인된 음성도 관찰 원문에서 읽도록 한다. 흔한 한국어·영어 부정/정상 표현을 보수적으로 검출해 기록을 재생성한다. `배제할 수 없다` 같은 불확실성은 허용한다. 모든 언어적 함의·근거 없는 양성 주장까지 검증하는 기능은 아니며, 유효한 표현의 과잉 거절 가능성도 있다. 반복 실패 시 관찰 원문 기반 fallback을 사용한다. P의 계획과 실제 SAY 교육 표시는 계속 분리한다.

검색 근거는 연령·주제·본문이 현재 판단에 관련될 때만 사용하도록 프롬프트를 강화했다. 낮은 관련성이나 제목/서지 위주의 결과는 무시하도록 한다. 검색 순위·자료·인덱스는 바꾸지 않았으므로 검색 품질 개선을 주장하지 않는다.

## 재현 가능한 오프라인 확인

저장소 루트에서 Python 3.12로 실행한다. 새 보고서 경로를 지정하고 기존 결과는 덮어쓰지 않는다.

```text
python -B -I scripts/run_v3_tests.py
python -B -I scripts/run_v34_offline.py --report /path/to/new-offline-report.json
```

두 도구는 SDK 전송 계층을 합성 fixture로 대체하고 Python socket 접근을 막는다. 실제 모델·API·자가채점·OS 수준 네트워크 격리 검증과 다르다. 원본 로그 분석 도구는 다음과 같으며 소스 로그는 Git 밖에 둔다.

```text
python -B -I scripts/analyze_v34_logs.py --runs /private/existing-comparison --output /path/to/aggregate.json
```

이 분석 도구는 원문·키·세션 ID를 내보내지 않고 횟수·관찰 ID·사유 코드·원시 파일 해시만 저장한다. 복합 질문 후보 수는 휴리스틱 집계로 임상 오류 수가 아니다.

검증 결과와 실제 로그의 원인 분석은 [v3.4 보고서](../reports/v34_20261016/REPORT.md)를 참고한다. 오프라인 통과를 대회 점수·안전 점수 유지·임상 성능 향상으로 해석하지 않는다.
