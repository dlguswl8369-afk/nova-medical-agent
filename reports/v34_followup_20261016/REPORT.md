# v3.4 후속 후보 — 답변 범위와 진료 진행

2026-10-16. 기준 `54e7e3e0fd4c651c718d53437783e91dd925ee7f`, 브랜치 `codex/nova-v3-4-consultation`, 기존 Draft PR #2의 후속 변경이다. 시작 시 로컬/원격 HEAD가 같고 미커밋 변경이 없음을 확인했다. 기존 후보·원장·보고서는 보존한다.

## 분석 근거

기존 [실제 로그 분석](../v34_20261016/REPORT.md), 비식별 집계, 진료 루프·상태·기록 코드와 테스트를 읽었다. C10 형식 오류, C03 부분 답변의 A 음성 확대, 설명·기록 누락 분석을 활용했다. 실제 샘플/자체 평가는 재실행하지 않았다.

사용자가 제공한 정보수집 점수(v3.2 8.24/25, v3.3 8.93/25), 의사소통 점수(4.67/15, 4.56/15)는 우선순위 근거다. 웹사이트의 세부 감점 사유가 없어 아래 코드 결함을 공식 점수 원인이라고 단정하지 않는다.

코드에서는 `과\s`가 내과·소아과를 복합 질문으로 판정하고, `정상` 부분 문자열이 질환명을 차단했다. 질문 목표별 답변 범위/횟수와 설명 후 반응 추적이 부족했다. 동일 질의를 context마다 검색했고 설명 후 새 환자 정보는 검색에서 제외했다.

## 변경한 동작

**오탐:** `consultation.py`는 명시적 복수 질문 절/진찰 동작을 검사한다. 단어 일부·접속 표현만으로 차단하지 않고 단일 targets 계약을 유지한다. 기존 접속 표현은 부분 답변 가능성 표시로만 사용할 수 있다. `record.py`는 명시적 정상/음성 서술·부정 술어로 범위를 좁히고 국소적인 인식 한계 표현을 허용한다. 질환명 예외 목록을 추가하지 않았으며 불확실성 단어가 있는 문장 전체를 면제하지 않는다.

**문진:** 새 `progress.py`의 `QuestionLedger`는 SDK 성공 응답 뒤에만 질문을 기록한다. 질문 전은 not_asked, 받은 답변은 기본 received_unreviewed다. 모름/거절/무응답은 별도 상태다. `review.answer_reviews`는 실제 질문의 observation_id, status, 답변 원문 quote를 사용한다. 상태는 confirmed/explicit_negative/unknown/ambiguous/unanswered/partial이며 partial에는 remaining이 필요하다. 모름/미답변을 확인·음성으로 승격하거나 질문/RAG를 답변으로 인용하면 거절한다.

이는 **모델이 판단한 답변 범위**이며 새 환자 사실이나 임상 검증이 아니다. 인용 일치가 질문 전체에 답했다는 뜻은 아니다. answer_reviews 생략 시 미검토로 남는다. 중요한 미해결 질문은 모델이 gaps에서 빼도 DONE에 연기 사유가 필요하다. 확인된 목표는 재질문하지 않고 미해결 목표는 진단·안전·처치를 바꾸는 high 공백 이유가 있을 때 한 번만 재질문한다(총 최대 2회). 이는 전체 질문 횟수나 전 환자 공통 체크리스트가 아니다.

목표는 NFC·공백·문장부호 정규화로 비교한다. 동의어/바꿔 쓴 목표는 완전히 판별하지 못하고 새로운 상태·시간대의 재평가 필요성도 모델 판단에 의존한다. 목표 요약은 최근 12개와 중요 미해결 최대 12개를 전달하며 생략 수를 표시한다. 원문은 기존 visible_facts 한도를 따른다.

**진찰/RAG:** 반복 문진 전에 감별·안전·처치를 바꿀 신체진찰을 검토하고 필요하면 EXAM을 선택하도록 프롬프트를 보완했다. RAG 권고는 다음 확인의 참고이며 현재 환자에게 그 소견이 있는지는 따로 확인한다. 특정 사례 정답·순서·진찰 최소 횟수는 넣지 않았다. 실제 모델의 선택 적절성은 미평가다.

**검색:** 같은 검색 질의의 마지막 패킷을 Run 메모리에서만 재사용한다. 새 질의는 재검색한다. 설명 후 단순 수긍/인사는 제외하되 새로운 환자 내용은 의사의 설명 문구와 분리해 검색에 포함한다. 이를 검증된 의학적 사실로 승격하지 않는다. retrieval_calls/cache_hits를 분리한다. 자료·인덱스·랭킹·패킷 상한은 유지하며 영구 캐시를 쓰지 않는다.

**소통/종료:** 불편/걱정 반응, 질문·진찰 이유, 판단/불확실성, 계획/안전망/이해 확인을 필요한 시점에 선택하도록 했다. 실제 SAY 성공만 전달 완료로 기록하고 이해 곤란·우려·무응답은 별도 표시한다. “네”는 응답 수신·이해 미입증이다. 다른 설명 목표가 앞선 이해 곤란을 지우지 않는다. 같은 목표·종류는 반응/새 이유를 확인하고 최대 두 번 설명한다. 이후에도 곤란이 남으면 상태를 보존하고 후속 지원·종료 사유를 명시한다. 설명 체크리스트로 무한 반복하지 않는다.

S/O 실제 원문과 누락 보완, A 관찰/추론 구분, P 계획/실제 설명 구분을 유지했다. usage 정산·상한·최종 기록 예약·request_id·지정 Doctor·TEST 금지·NFC 30자 상한도 유지한다. 자동 절단·행동 변환은 추가하지 않았다.
